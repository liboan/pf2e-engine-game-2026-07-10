# Working rules

W2 and W3 are accepted. Their code, tests and guidance are authorized for publication on the codex/pf2e-content-w2-w3-delivery branch. The W3 execution heartbeat is paused; no follow-on wave is authorized. See docs/work-log/ACTIVE.md for final publication verification. No force-push, main merge or overwrite of other work; verify accepted ancestry, remote head and clean checkout. A new PR is optional, not required.

## Direction, ownership and checkouts

- Build a local Python PF2e engine with a simple terminal interface. Keep literal local state; no browser, server, network or distributed-state machinery.
- Current authority is the user-authorized Content W3 working model in [docs/plan/04-delivery-and-checks.md](docs/plan/04-delivery-and-checks.md). The Astra/high coordinator owns guidance, scope, assignments and recovery. It reads recovery evidence and repository metadata, not implementation or rules-source content. Implementation inspection and wave integration belong to an actual implementation owner.
- Use full Codex tasks as the primary team: two Terra/high implementation owners, one Luna/high owner for established mechanics, and two Sol/high reviewers. This supersedes Terra-only routing and native-subagent-only communication. Use Astra/high for substantial unresolved design/rules questions only. Do not silently substitute models; evaluate actual capability and quality through work.
- Reuse the existing six W1 tasks and their current worktrees for W3; do not create replacements. All tasks and any authorized descendants must retain the exact title prefix `PF2e Content W1 — `. One managed worktree per task; reuse it through repairs. No nested worktrees or shared mutable checkout. Before W3 edits, advance your existing checkout to the coordinator's common accepted-W2-plus-guidance baseline, preserving prior branches, review tests and uncommitted work. A new assignment branch in the same checkout is allowed; no destructive reset. Reviewers inspect explicit delivered commits in their own checkout. Leave unrelated branches/worktrees alone.
- Give a coherent playable mechanic family one owner across legal grants, runtime, persistence, terminal and tests. Retain that owner through repairs. One such owner also leads wave integration in its own checkout; no separate integration-only translator by default.
- Direct scoped `send_message_to_thread` messages are authorized. Send a message only to the task whose next action changes. Routine runnable delivery and repair go owner ↔ assigned reviewer. The reviewer sends accepted commits/tests to the integration lead; owners do not duplicate acceptance reports. The integration lead contacts the coordinator for assembled acceptance or a decision it cannot resolve. Contact the coordinator earlier only for scope, priority, shared-contract decisions or unresolved blockers requiring coordinator action. Do not CC the coordinator for awareness, environment checks, ordinary checkpoints, repair-ready updates or per-family acceptance; do not forward a handoff already delivered directly. Exact peer IDs are in ACTIVE. This replaces the W1 instruction to send first checkpoints to both reviewer and coordinator. Native collaboration tools address native subagents only. No acknowledgement-only messages, receipt loops or repeated progress pings.
- When only another task's work remains, END YOUR TURN. Do not loop on waits, sleep, status checks, transcript reads or commentary. An owner with a dependency reports it once and ends unless independent useful work remains. Reviewers finish useful preparation/review, report findings and end until a delivered change needs checking.
- Coordinator alone maintains plans and work logs. Owners may maintain scoped source/implementation notes and tests. Supply exact files/symbols, analogous test/helper, interpreter/PYTHONPATH/cwd, last runnable public probe, API contract and unfinished dependencies in compact handoffs.

## Correctness, checks and evidence

- Check legal grants, source expectations and material differences before implementation; cite applicable PF2e sources in compact notes/tests. Before altering production behavior or assertions for a failing test, verify the disputed source and actual fixture. Never silently approximate unsupported behavior.
- Run focused bounded tests frequently; review complete runnable families independently against the actual engine and sources. Preserve real continuous public play, save/load, terminal, adverse cases and bounded performance evidence. Run the complete suite on assembled integration. Plans and definition tests are insufficient.
- One synchronous pytest process per worker; no xdist, watches or background tests. Keep one broad integration active. Name concrete hazards for holds, not a global test-slot lock. Reuse `tools/integration_checkpoint.py`; verify the interpreter in each checkout. No copied `.venv` assumption.
- Bound time/input/output for every probe. At integration, idle/completion and handoff, report task-owned test/probe process status. Stop only confirmed unused task-owned descendants after identity verification and graceful exit; never kill by name or stop unclear shared services. Unavailable process inspection is a stated limit, not a cleanup claim.

## Recovery, accounting and decisions

- [ACTIVE](docs/work-log/ACTIVE.md) replaces stale queue state and records task ID/title, cwd, branch/base, model/owner, peer IDs, scope, dependencies, executable checkpoint and next action. Detailed output stays with owners/reviewers. Update central recovery at meaningful milestones, not by waking the coordinator for bookkeeping. Final handoffs are normally 250–400 words.
- One coordinator heartbeat at about five minutes is a fallback while active, with no worker polling automations. On a wake inspect compact state once, handle actionable changes, and end promptly if none. Notify only meaningful changes, completion, failures or required user action. Pause at milestone closure or explicit user pause.
- Cost monitoring belongs to the audit task. Reuse the existing deterministic `tools/log_agent_usage.py` when accounting is needed, never invent ledger scripts/frameworks. The ignored local `docs/work-log/agent-runs.json` may be absent. Preserve actual identities/boundaries, deduplicated request usage including compactions, observed model/effort, cached input as a subset, and null/reason for unavailable values. Ordinary repairs keep assignment boundaries.
- Resolve P0 blockers with the structured user question tool; resolve P1 before dependent choices, continuing independent work. Routine reversible decisions use judgment. A failing check is evidence to isolate and repair, not permission to lower acceptance. Surface the smallest material decision with reviewable evidence.
